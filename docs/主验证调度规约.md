# 主验证三节点调度规约（SPEC）

> 规约先行：本文件先于任何调度代码修改。所有调度行为必须可追溯到本规约条款；代码与规约冲突时，先改规约（留痕），再改代码。

## S1 工作单元（Work Unit）定义
- WU-1 最小工作单元 = 一条任务清单行（一个 `python3 -m sea_pilot.*` 调用，带唯一 `--tag`）。
- WU-2 每个工作单元的完成判据：模块正常退出（exit 0）**且**产物通过 §S3 有效性门。
- WU-3 复制单元 = 同一配置不同 `--seed` 的工作单元集合；seed ∈ [1, 30]（O/G 车道）、[101, 110]（Q 车道）。**禁止**同 seed 改 tag 冒充复制。

## S2 车道与家族分离
- L-1 车道绑定固定模型家族，运行期不得切换：O=ornith-1.5-35b（qwen35moe）、G=gemma4:26b（gemma）、Q=qwen3.8-27b（qwen35）。
- L-2 主体、评分器、红队/评审必须落在 ≥3 不同家族；评分任务不得与被试同车道。
- L-3 每车道内部严格串行；跨车道并行。Mac Studio 上 LM Studio 与 Ollama 大模型不得同时驻留。

## S3 有效性门（Validity Gates）
- V-1 车道启动预检：内容有效性探测（content / reasoning_content / reasoning 三字段兼容），空内容或退化重复即拒绝启动。
- V-2 运行期模型一致性守卫：响应 `model` 字段与车道声明不符时等待重试（≤8 次），持续不符则任务失败。
- V-3 记录级有效：`picked` 非空才算完成（空选择重试）；重跑续传时清理空选择记录。
- V-4 换模型/换版后必须重跑 H8 锚点电池与 H9 校准，方可进行主 run。

## S4 参数诚实性
- P-1 重放语料仅 30 模拟日（arXiv 2019-09）；`--days 90` 在语料扩展前属于虚标，**禁止**出现在任务清单中。当前 replay 任务一律 `--days 30`。
- P-2 臂级单元（S0–S3 × 对抗环境）在臂感知模块落地前只能以注释行存在。
- P-3 所有产物标注 [进行中]/[设计] 状态，禁止虚构数据进入论文。

## S5 可恢复性
- R-1 任务级：完成旗标 `pilot/results/dispatch_flags/{lane}_{md5}.done`，中断重跑自动跳过。
- R-2 记录级：参与者 × 日 原子落盘（tmp+rename），重跑仅补缺失记录。
- R-3 进度可观测：任何时刻 `python3 -m sea_pilot.dispatch_progress` 输出三车道进度条，数据源仅为旗标与 jsonl 日志（不依赖进程状态猜测）。

## S6 验收测试（TDD）
- T-1 `test_dispatch.py` 全绿是启动调度的前置条件。
- T-2 覆盖：任务清单可解析性/唯一性、seed 真独立性、进度计算正确性、预检守卫拒绝空内容。

## S7 性能条款（2026-10-05 修订，用户已批准全套加速方案）
- P-4 **思考预算封顶**：按家族分档（实测各家族推理长度差异显著）——
  O 车道（ornith）：初始 2400 / 重试上限 4800；G/Q 车道（gemma/qwen）：初始 1200 / 上限 2400
  （协议 v2.1）。理由：实测推理型模型将 4500 预算几乎烧满（~100–300s/调用）；
  ornith 在真实决策提示下 1200/2400 频繁返回空内容（推理字段耗尽预算），故 O 档放宽。
  该参数按家族写入论文参数表（声明参数）。
- P-5 **协议版本隔离**：v1（4500/16000）产物一律作废（归档 `archive_protocol_v1/`，
  文件名保留备查），禁止与 v2 记录混合分析。
- P-6 **4xx 快速失败**：客户端错误（HTTP 4xx，如模型被卸载）属确定性故障，
  后端不得重试，立即返回失败标记；恢复服务后按 R-1/R-2 续跑补齐。
- L-4 **车道内并发分片**：允许同车道按 `--agent-start` 分片并行（同家族、同模型、
  同节点，不违反 L-1/L-2）。本地车道 ≤4 分片，云车道 ≤8（S8 修订）。分片共享
  run seed，以 (seed, agent-start) 二元组保证任务唯一性。
- L-5 Ollama 节点（G/Q）的服务端并发（OLLAMA_NUM_PARALLEL=4）由节点管理员手动开启；
  未开启前子车道在服务端排队，不产生错误，仅无加速。
- L-6 LM Studio（O 车道）须保持模型常驻加载；若出现 "No models loaded"（400），
  子车道快速失败退出，由管理员在 Mac 上重新加载模型（lms load ornith-1.5-35b，
  建议关闭自动卸载/开启 JIT）后按 R-1 续跑（`bash sim/run_dispatch_o.sh`）。
- L-7 车道进程必须 `setsid nohup ... </dev/null` 脱离会话启动：调用方 shell
  退出时进程组会被连带终止（2026-10-05 教训：15:53 启动的 10 条车道 80 分钟内全灭）。

## S8 OpenRouter 云车道条款（2026-10-05 修订，用户已批准全套云方案）

  6 并发分片）与 F 车道（nvidia/nemotron-3-super-120b-a12b:free，免费，锚点 10 run，
  单流节拍）。G 车道（gemma4:26b 本地）由主力降为锚点（30→10 run，seed 1–10 不变，
  已有记录协议兼容保留）。家族结构：主力 O(ornith) + C(ling)，锚点 Q(qwen) +
  G(gemma) + F(nemotron)——仍满足 ≥3 家族分离，且主/锚分工写入论文参数表。
- R-6 **密钥管理**：OPENROUTER_API_KEY 永不入库；经 gitignored 的
  `sim/.openrouter_key`（`export OPENROUTER_API_KEY=...`）注入。泄漏即吊销重发。
- R-7 **免费配额纪律**：F 车道是免费配额唯一消费者；全账户 ≤1000 次/日，
  以 SEA_MIN_INTERVAL=100s 节拍（≤864 次/日，留余量）。429 响应延长退避
  （60s×attempt）；连续 12 次失败则该 agent-day 记空，按 R-1 续跑补齐。
- R-8 **成本熔断**：付费车道后端累计 usage.cost 超过 SEA_COST_CAP（默认 $2/进程）
  立即熔断返回失败标记；全车道预估总成本 ~$3，月度限额 $100 由 key 侧硬约束。
- R-9 **禁选提供方**：OpenRouter 侧不得选用 openai/google/anthropic 三家的模型
  （用户约束）；gemma 家族仅由本地 G 车道承担。

  文本误匹配），已在运行的车道自动跳过。重跑前必须按 PID 精确清理旧 runner
  及其 python 子进程（孤儿 python 不随 runner 被杀，需单独按 --tag 模式清理）。
