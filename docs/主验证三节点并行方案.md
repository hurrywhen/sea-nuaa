## 3. 容量测算（生成受限）

按运维实测口径：推理型模型每次调用输出 1.5k–3k token（max_tokens 3000–4500），15 调用/主体·日。

- 聚合产能：9.1M tok/日 ÷ (1.5k–3k tok/调用 × 15 调用/主体·日) ≈ **200–400 主体·日/日**
- 单队列轮次（30 主体 × 90 日 = 2,700 主体·日）：**7–13.5 日**（三车道并行，按车道分摊）
- 相对单 Mac 串行：**约 3 倍加速**

### 主验证规模情景

| 情景 | 规模 | 主体·日 | 三节点墙钟 |
|---|---|---|---|
| A. 试点补齐 + 三家族复制（当前可跑） | 3 家族 × 30 run × 30主体 × 90日（Q 车道先 10 run） | ~189k | **16–31 个月** |
| B. 缩减版：3 家族 × 10 run × 30主体 × 90日 | 81k | ~7–13 个月 |
| C. 核心行为检验优先（H1'–H7' 关键单元） | 10–20k | **1.5–3 个月** |
| D. 预注册全规模（100–300 主体 × ≥30 run × 7 臂 × 3 家族） | ≥10⁶ | 年以计，本地不可行，须 API 补充 |

**结论**：三节点并行把单队列轮次从"月级"压到"周级"，情景 C（核心单元先行、按预注册优先级排序）是本地资源的现实路径；情景 D 仍需 API 预算（$10³–10⁴ 口径不变）。

## 4. 使用方法

```bash
cd sim
python3 -m sea_pilot.make_dispatch_tasks          # 生成 dispatch_tasks/tasks_{O,Q,G}.txt
bash run_dispatch_3node.sh                        # 三车道并行启动（各车道内部串行）
tail -f pilot/results/dispatch_{O,Q,G}.log        # 监控
```

- **断点续跑**：任务级旗标（`pilot/results/dispatch_flags/`）+ 模块内参与者级 jsonl 原子落盘，中断后重跑同一命令即续传。
- **健康守卫**：每车道启动前做内容有效性探测（兼容 content / reasoning_content / reasoning 三种推理字段）；运行中 `OpenAICompatBackend` 有模型一致性守卫（响应 model 字段不符则等待重试）。
- **臂级主验证单元**（S0–S3 × 对抗环境）以注释行写入任务清单，待臂感知模块落地后取消注释。
